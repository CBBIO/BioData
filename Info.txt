This page shows how to connect to the **BioData** PostgreSQL database (with **pgvector** embeddings) from Python, and gives a concrete example of how to do **nearest‑neighbor similarity search** on protein embeddings and retrieve their GO annotations.

It assumes that BioData is already loaded (via Zenodo or the PIS tools) and that:

- PostgreSQL is running on `localhost:5432`
- Database: `BioData`
- User: `usuario`
- Password: `clave`

Adjust these values to match your setup.

## 2. Basic Connection from Python

```python
import psycopg
from pgvector.psycopg import register_vector

conn = psycopg.connect(
    "postgresql://usuario:clave@localhost:5432/BioData",
    autocommit=True,
)

# Enable pgvector support (for half-precision embeddings)
register_vector(conn, "halfvec")

with conn.cursor() as cur:
    cur.execute("SELECT COUNT(*) FROM sequence_embeddings;")
    total = cur.fetchone()[0]

print(f"Total sequence embeddings in BioData: {total}")

```

This confirms that:

- The DB is reachable.
- The `sequence_embeddings` table (from PIS) is present.

## 3. Exploring Available Embedding Types

BioData stores multiple embedding types (ESM, ProtT5, ProstT5, ANKH3, ESM3c, etc.) in the table `sequence_embedding_type`.

```python
import pandas as pd

with conn.cursor() as cur:

        SELECT id, name, model_name, task_name, description
        FROM sequence_embedding_type

    """)
```

Pick the `id` corresponding to the model/layer you want to use.

## 4. Use Case – Nearest‑Neighbor Search in Embedding Space

### Goal

Given a **query protein** (by UniProt ID), find the **most similar proteins** in BioData using vector similarity on a specific embedding model + layer, and then fetch their **GO annotations**.

This showcases how to use BioData as a **lookup table** for:

- Embedding‑based similarity search.
- Quick retrieval of experimentally supported GO terms for nearest neighbors.

---

### 4.1 Helper: Get embedding for one protein

We’ll assume you know the UniProt accession (stored as `protein.id` in this schema) and the embedding type ID you want to use (`embedding_type_id`).

```python
import numpy as np

def get_protein_embedding(conn, uniprot_id: str, embedding_type_id: int, layer_index: int = 0):
    """
    Fetch the embedding vector for a given UniProt ID, model type, and layer.
    Returns a NumPy array or None if not found.
    """
    with conn.cursor() as cur:
        cur.execute("""
            SELECT se.embedding
            FROM protein p
            JOIN sequence s ON p.sequence_id = s.id
            JOIN sequence_embeddings se ON se.sequence_id = s.id
            WHERE p.id = %s
              AND se.embedding_type_id = %s
              AND se.layer_index = %s
            LIMIT 1;
        """, (uniprot_id, embedding_type_id, layer_index))
        row = cur.fetchone()

    if row is None:
        return None

    # pgvector returns a Python list / tuple; convert to NumPy array if you like
    return np.array(row[0], dtype=np.float32)

```

---

### 4.2 Helper: Find nearest neighbors

We use the pgvector `<->` operator (L2 distance) on the `embedding` column:

```python
def find_nearest_neighbors(conn, query_embedding, embedding_type_id: int, layer_index: int = 0, k: int = 10):
    """
    Find k nearest neighbors in sequence_embeddings for a given embedding.
    Returns list of (protein_id, distance) tuples.
    """
    with conn.cursor() as cur:
        cur.execute("""
            SELECT p.id AS protein_id,
                   se.layer_index,
                   se.embedding <-> %s::halfvec AS distance
            FROM sequence_embeddings se
            JOIN sequence s ON se.sequence_id = s.id
            JOIN protein p ON p.sequence_id = s.id
            WHERE se.embedding_type_id = %s
              AND se.layer_index = %s
            ORDER BY se.embedding <-> %s::halfvec
            LIMIT %s;
        """, (query_embedding, embedding_type_id, layer_index, query_embedding, k))
        rows = cur.fetchall()
    return rows

```

Notes:

- `register_vector(conn, "halfvec")` allows passing a NumPy array directly for `%s`.
- If you prefer cosine distance, you can use the `<=>` operator (if enabled for your pgvector version).

### 4.3 Helper: Fetch GO annotations for a list of proteins

The BioData schema stores GO terms in:

- `protein_go_term_annotation` – links proteins to GO IDs and evidence codes.
- `go_terms` – describes each GO term (category + description).

```python
def fetch_go_annotations(conn, protein_ids):
    """
    Given a list of protein IDs, fetch their GO annotations.
    Returns a dict: {protein_id: [(go_id, category, description, evidence_code), ...], ...}
    """
    if not protein_ids:
        return {}

    with conn.cursor() as cur:
        cur.execute("""
            SELECT pga.protein_id,
                   pga.go_id,
                   gt.category,
                   gt.description,
                   pga.evidence_code
            FROM protein_go_term_annotation pga
            JOIN go_terms gt ON gt.go_id = pga.go_id
            WHERE pga.protein_id = ANY(%s)
            ORDER BY pga.protein_id, pga.go_id;
        """, (protein_ids,))
        rows = cur.fetchall()

    annotations = {}
    for protein_id, go_id, category, description, evidence_code in rows:
        annotations.setdefault(protein_id, []).append(
            (go_id, category, description, evidence_code)
        )
    return annotations

```

### 4.4 End‑to‑end example

Putting it all together for one query UniProt ID:

```python
QUERY_UNIPROT = "P12345"     # replace with a real UniProt accession in BioData
EMB_TYPE_ID   = 1            # choose from df_types above
LAYER_INDEX   = 0            # e.g. layer 0

# 1) Get query embedding
query_emb = get_protein_embedding(conn, QUERY_UNIPROT, EMB_TYPE_ID, LAYER_INDEX)
if query_emb is None:
    raise ValueError(f"No embedding found for {QUERY_UNIPROT} (type {EMB_TYPE_ID}, layer {LAYER_INDEX})")

# 2) Find nearest neighbors
neighbors = find_nearest_neighbors(conn, query_emb, EMB_TYPE_ID, LAYER_INDEX, k=10)
neighbor_ids = [row[0] for row in neighbors]

print("Nearest neighbors (protein_id, distance):")
for protein_id, _, dist in neighbors:
    print(f"  {protein_id}\\t{dist:.4f}")

# 3) Fetch GO annotations for neighbors
annotations = fetch_go_annotations(conn, neighbor_ids)

print("\\nGO annotations for neighbors:")
for protein_id in neighbor_ids:
    anns = annotations.get(protein_id, [])
    print(f"\\nProtein {protein_id}:")
    if not anns:
        print("  (no GO terms)")
        continue
    for go_id, category, desc, evidence in anns:
        print(f"  {go_id} [{category}] ({evidence}) - {desc}")

```

**What this demonstrates:**

- Use BioData as a **vector search index** over multiple PLM embeddings.
- For a single query protein, you can:
    - Get nearest neighbors in embedding space (sequence similarity in a rich learned representation).
    - Immediately retrieve **experimentally supported GO annotations** for those neighbors.
    - Use this to:
        - Propose functional annotations for the query.
        - Explore related proteins by GO category (molecular function, biological process, cellular component).
        - Build downstream tools for annotation transfer, clustering, or visualization.

## 5. How to Integrate in Your Own Project

- Put the connection + helper functions into a small module, e.g. `biodata_client.py`.
- Use the same connection URL in notebooks, batch scripts, or web APIs.
- Choose different `embedding_type_id` / `layer_index` pairs to:
    - Compare performance of different PLMs.
    - Mix early layers (more local/structural signals) vs final layers (more semantic/functional signals).
